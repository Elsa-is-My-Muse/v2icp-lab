# 用五个实验理解车、桩、后台

## 实验一：谁主动连接谁？

启动自动模式，看事件 `TLS_CONNECTED → TX → RX`。发起连接和 HTTP 请求的是模拟 EVCC，后台等待并应答，中继只转发加密字节。后台不是主动连接 EVCC 的另一台 TCP 客户端；本模型中的“后台下发”是 HTTP 响应携带调度字段。

界面中的三块不是三台真实设备，都是一台 PC 的独立网络组件。TLS 验证对象是后台；中继没有后台私钥。

## 实验二：全量、增量和安全字段

单步第一帧看 seq=0；记下身份和八个车辆信号。再单步，不变字段省略，但身份、seq、h2_stat、bat_stat 仍出现。将 odo 改成 5100 并应用，下一帧带新 odo，再下一帧省略它。后台必须合并增量，不得将省略字段当零值。

本项目 seq 0..255 回绕；回到零再全量。车端进程/新连接重新从零开始。具体规范版本的全部序列语义仍需持有规范者复核。

## 实验三：原始值和物理值不相同

将距发车时间设为 60 分钟。响应 `driveoff:12`，因为本模型分辨率为 5 分钟。输入的是后台业务值，发出的才是缩放后的 raw；不能把 60 直接作为 60 分钟的 raw。倒计时按本项目向上取整量化，小于 5 分钟时也可能显示 raw=1。

温度 -1 是有效温度，本模型温度 SNA 是 -51。其他数值未知通常使用 -1。不要把所有负数统一当错误，也不要把所有未知统一当正常。枚举含义不能仅凭名字推测，见信号字典和目标规范。

## 实验四：车到后台、后台到车各是什么？

车上报：里程、能量/时间需求、充电和安全状态、身份/序号。

后台响应：对应身份/序号、发车倒计时、预调节目标、温度和里程/SOC目标。每轮正常响应是后台当前计划快照。

改变 target_soc 并观察 RX 只是证明后台计划到达和解析成功；并不意味着 SOC 已达到目标，更不意味着此软件能控制真实电池。真机需整车策略验证、任务队列、CAN接口和执行反馈。

## 实验五：失败能否污染有效数据？

1. 单步先得到有效计划。
2. 注入错误 VIN 或 seq，再单步，观察 `RESPONSE_REJECTED`；有效 RX 与计划仍保持上次值。
3. 注入丢包，再单步，观察 TIMEOUT 和 attempt=2，同序号同内容重发。
4. 注入超长响应，观察断开；这是有意的安全停止，不自动无限重连。

## 与真实充电连接的关系

本机演示只有数据通道，未建立实际 ISO 15118 充电连接。真机目标是原充电连接继续工作，另开独立 V2ICP 连接，通过允许的网络接入到运营后台。InternetAccess 不是“切换成后台连接然后关闭充电 TCP”。

真实网络上两条流应使用不同上下文、独立超时；路由是否可达、VAS是否协商成功、地址如何分配，都不由这个固定字节中继替你完成。
