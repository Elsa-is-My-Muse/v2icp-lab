# 从PC实验迁移到现有EVCC / SECC

## 0. 这不是把Python直接放进MCU

此项目已经证明本机双向应用数据可被编码、加密、转发和校验。真机还缺PLC/VAS/真实IPv6路径/固件连接上下文/整车接口。下列是集成工作分解，不是“已经完成适配”的说明。

开始适配前，先确认目标板卡的MCU、接口、RAM预算、RTOS和第三方协议库版本。工程配置不能代替板图和实物检查；本仓库不包含特定公司的固件或板级适配。

## 1. 先确定后台接入合同

让后台运营方提供并确认：

- 后台域名/IPv6地址、端口（生产接口应按项目约定，通常HTTPS端口）、HTTP路径。
- DNS/时间源/证书链、预期服务端身份、凭据发放和轮换流程。
- 每车身份和密码的安全写入方式；不得复用公开demo凭据。
- 各信号单位、枚举、SNA、更新策略、超时/重试/恢复、幂等和故障行为。
- 测试环境、匿名测试车辆、后台日志关联方式和验收标准。

**没有统一的VDV261服务器地址。** 不能把本机 `::1` 或某个示例URL刷入所有车辆当作真实服务器。

## 2. SECC先解决“能否到达”

1. 保留现有ISO15118连接与充电状态机。
2. 按目标ISO15118/项目规范实现并测试InternetAccess相关VAS发现/选择/授权及生命周期；本仓库没有这段EXI实现。
3. 明确PLC接口到后台上联的IPv6数据路径，验证地址来源、前缀、NDP/RA、路由、MTU与访问控制。不能只验证SECC主控本身可访问后台。
4. 现有W5500 socket路径不能无验证地当成IPv6网关；需评估实际硬件工作模式、主机网络栈方案或独立IPv6网关。不要将“加IP_FORWARD宏”当作完成设计。
5. 本项目固定TCP字节中继只适合教学：它只连一个配置好的目的地址，不会替EVCC路由任意目的IP，也不代表标准要求特定代理协议。

网络路径最好先用受控低压以太网台架验证，再引入PLC，避免把应用协议、VAS与底层链路问题混在一起。

## 3. EVCC增加独立数据连接

至少为连接A（原充电）与B（V2ICP）各自保留：

| 上下文 | A：充电连接 | B：V2ICP数据连接 |
|---|---|---|
| socket / TLS对象 | 原逻辑保持 | 新对象，不覆盖A |
| 收发缓冲 | EXI/V2G帧 | 有界HTTP头/体与JSON |
| 状态与计时器 | 原充电状态机 | 独立连接、发送、等待、重试、停止 |
| 地址/身份 | 原SDP及会话确定 | 运营方配置与证书身份 |
| 退出清理 | 遵循充电协议/安全要求 | 关闭B不得误关A或全局PLC |

不要求“必须把所有库重写成实例化”；可采用独立连接上下文或驱动支持的第二个实例。关键是不得复用单例socket、TLS对象或全局缓冲导致互相覆盖。原充电TCP端口以实际SDP与工程逻辑为准，不把旧默认50000描述成标准强制。

推荐低优先级非阻塞状态机/独立任务，网络I/O有界等待。若底层库只有单连接能力，先解决架构限制再接业务，不靠延时碰碰运气。

## 4. 应用数据与整车边界

```text
上报：授权CAN/VCU只读 → 数值有效性和SNA → 车辆快照 → 首次全量/后续增量
下发：TLS/HTTP → JSON长度/类型/范围 → seq/VIN → 单位/时效 → 本地策略 → 目标队列
```

后台返回目标SOC，不是立即强制写SOC；返回预调节需求，不是允许绕过BMS/HVAC保护。未知安全信号保留未知，由本地策略决定如何处理。不要凭示例给真实CAN总线发送控制帧。

`embedded/v2icp_boundary.*` 提供纯C的目标接纳边界；它没有CAN、驱动、RTOS或完整协议。主机示例通过只说明这些函数在主机可编译运行。

## 5. 连接与资源验收

- 接入后台断网/慢响应/错误证书/错误序号/503/超长包时，观察A是否仍按既定充电策略工作。
- 测握手峰值RAM、任务栈、CPU、buffer池、socket数量和动态分配失败；阈值由项目预算确定，不编造通用安全数字。
- 检查计划新鲜度、断线保留/清除规则、序号回绕、重连后全量和长时恢复。
- 将数据服务失效与充电安全故障区分，并由整车安全设计确定最终动作；此项目不替你决定“必须继续充”或“必须停充”。
- 使用硬件检查清单与记录模板，保留实际测量证据。不能把PC回环测试写成真实PLC或整车通过。

## 6. 贡献适配代码前

先确认自己的代码和依赖允许公开；把板级适配与通用协议分层，敏感DBC/密钥/厂商包留在仓库外。提交新适配时附匿名接口说明、板卡版本、编译器、测试范围和未测项，而不是上传整个私人固件工程。
